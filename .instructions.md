# ElementTracker2026 - Development Agent Instructions

## 🎯 Projektziele & Kontext

**ElementTracker2026** ist eine GPS-Tracking-Anwendung mit:
- **Backend:** Node.js/Express + TypeScript + PostgreSQL (mit PostGIS)
- **Frontend:** React/Next.js 13.5+ mit Tailwind CSS
- **Auth:** JWT mit Refresh-Token Mechanismus
- **Features:** Elementverfolgung, Admin-Genehmigung, Fotoupload, Kartendarstellung

## 📋 Wichtige Architektur-Details

### Backend
- JWT Tokens: Access (24h) + Refresh (7d)
- Token-Refresh bei 401 mit TOKEN_EXPIRED
- Admin-Verifikation: verifyAdminToken Middleware
- Dateiablage: `backend/public/uploads/`
- Ports: 3000 (Backend), 3001 (Frontend)

### Frontend
- Next.js mit App Router
- Dynamisches MapViewer Laden (SSR: false) wegen Leaflet/window
- localStorage: `elementtracker_token`, `elementtracker_refresh_token`
- Tailwind classes: rounded-2xl, rounded-3xl, backdrop-blur-sm, gap-3, etc.

### Datenbank
- PostgreSQL mit PostGIS Extension
- Schemas: elements, entries, pending_entries, admins, refresh_tokens
- PostGIS Funktionen: ST_SetSRID, ST_MakePoint, ST_X, ST_Y

## 📝 Script-Wartung Checklist

### Bei NEUEN Dependencies (npm install):
- `install.sh`: package.json Update dokumentiert?
- `backup.sh`: package.json in Backup eingeschlossen?
- `restore.sh`: npm install in Review?

### Bei NEUEN Umgebungs-Variablen:
- Backend `JWT_SECRET`, `CORS_ORIGIN` etc. in `.env`?
- `install.sh`: dotenv-Setup korrekt?
- `restore.sh`: .env richtig wiederhergestellt?

### Bei NEUEN Verzeichnissen/Dateien:
- `backend/public/uploads/` oder ähnlich?
- `install.sh`: chmod und Verzeichnis-Erstellung?
- `backup.sh`: Kritische Dateien eingeschlossen?
- `.gitignore`: Sensible Dateien ausgeschlossen?

### Bei Port-Änderungen oder neuem Service:
- `cleanup.sh`: Alle Ports in kill_port aufgelistet?
- `start.sh`: Alle Services gestartet?
- CORS & Verweis auf neue Ports konsistent?

### Bei Datenbank-Änderungen:
- `setup/init.sql` aktualisiert?
- `install.sh`: Neue Migrations durchgeführt?
- `backup.sh`: DB-Dump Strategy konsistent?

## 🔄 Regeneration Workflow

Wenn der Agent diese Instructions überprüft:

1. **Vor Feature-Implementierung:** Scripts scannen auf Erkenntnisse
2. **Während Entwicklung:** Bei Script-Erkenntnissen einweben
3. **Nach Feature:** Vollständige Script-Überprüfung durchführen
4. **Im Deployment:** Sauberer Test mit cleanup.sh + start.sh

## 🚨 Kritische Regeln

- ❌ **NIEMALS** .env mit Passwörtern in Versionskontrolle committen
- ✅ `.env` Beispiel-Datei: `.env.example`
- ✅ Sensible Secrets: `backend/.env` im `.gitignore`
- ✅ Feature = Backend API + Frontend + Tests + Script-Update
- ✅ Tokens immer mit richtigem Secret generieren (JWT_SECRET)
- ✅ Refresh-Token bei 401 + TOKEN_EXPIRED Code automatisch
- ✅ Alle neuen Endpoints mit CORS berücksichtigen
- ✅ PostGIS Funktionen nutzen für räumliche Daten

## 📊 Performance & Sicherheit

- JWT_SECRET: Mindestens 32 Bytes (wird auto-generiert)
- Passwörter: bcryptjs mit 12 Salt Rounds
- File Uploads: MAX_FILE_SIZE prüfen (Backend)
- Datenbank Passwords in Production: ÄNDERN nach install.sh
